## 結果

建立 T-047 後續實證可重用的**隔離 run owner manifest 與清理／復原機制**。每次執行以 UUID runId 建立新的 OS 暫存根 `hadome-e2e-*`，在其下建立 `profiles/default`、`workspace`、`ports`、`logs`、`artifacts`。`owner-manifest.json` 原子寫入，包含 runId、caseId、開始及結束時間、owner PID 與程序啟動識別、子程序 PID／啟動識別／獨有參數、預定隔離埠、清理狀態、exitCode（未知時為 null），以及 Git HEAD、Node、Playwright core、Chromium revision／版本及擴充版本；未實測的 editor／protocol 以 null 表示。

透過 `runCase` 執行案例；成功、assertion 失敗、timeout、取消均記錄結果並進入 finally 清理。子程序使用 `spawnOwned` 建立，清理時逐一核對 PID、`ps` 啟動時間與 run 專有參數才送訊號；所有權不明時拒絕終止並留下 `needs-manual-review` 和 profile，**不以程序名稱模糊 kill**。清理前先保存 manifest，清理後保留 manifest、logs 與 artifacts，僅移除預設可丟棄的 profile／workspace／ports。

`SIGKILL` 無法觸發 finally：已實作 `inspectRun(root)` 與 `recoverRun(root)`，只對明確指定的暫存 run root 做安全核對。若原 owner 還在執行便拒絕復原；owner 已結束時，核對每個子程序識別後終止並回收隔離目錄，保留台帳。對非法根目錄、符號連結、未知 PID 身分，採 fail-closed。預先取消不得進入案例函式；取消與 spawn 並發時先等待子程序完成台帳登記，再執行清理。

## 使用方式

```sh
# 單獨驗證 T-046
node --test test/e2e-run.test.js

# 識別某次被中斷的 run：預設唯讀，不執行 kill 或目錄刪除
node tools/e2e-recover.js /absolute/path/to/hadome-e2e-<run-root>

# 只有 owner 已結束且識別核對通過時，才嘗試清理該單一 run
node tools/e2e-recover.js /absolute/path/to/hadome-e2e-<run-root> --recover
```

上述 `<run-root>` 是使用者必須以真實 manifest 所在的**完整絕對路徑**代入的說明占位字，不是可直接複製的實際路徑。請先以唯讀命令確認 manifest、PID、啟動時間與 profile 路徑。絕不可用本工具掃描或終止正式工作程序。
