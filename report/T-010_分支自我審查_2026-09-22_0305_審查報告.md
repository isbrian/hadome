## 發現

### W1 `warn` — `pairedFor()` 每秒建立整個 settings 物件

**位置**：[extension.js:405-413](../extension.js#L405-L413)、觸發點 [src/bridge.js:730](../src/bridge.js#L730)

主橋的 `pollClaim` 以 `CLAIM_POLL_MS = 1000` 的頻率跑，第一件事就是 `if (isPaired()) return;`。
而 `paired` 傳的是 `pairedFor` 函式，它為了拿一個埠號呼叫了整個 `settings()`——那裡面包含
約 30 次 `c.get()` 與 `mergeDenylist()`，後者會**對使用者 denylist 的每一條編譯一個
`new RegExp`**（[src/tools.js:65-80](../src/tools.js#L65-L80)）。

預設 denylist 是空的所以影響小，但使用者自訂 20 條規則時，就是每秒編譯 20 個 regex、
永遠跑下去。這是本分支引入的——改動前 `pollClaim` 完全不碰 settings。

子橋不受影響（它們傳的是布林 `true`，不會走到函式）。

**建議**：`pairedFor()` 只讀埠就好，不要叫 `settings()`。

### W2 `warn` — `npm test` 在空席不足時靜默 exit 0

**位置**：[test/seat-check.js](../test/seat-check.js)

腳本開頭若找不到 3 個空席（例如本機正在跑 hadome、或 CI 上埠被佔），會印一行訊息然後
`process.exit(0)`。對互動式手動執行這很合理，但掛上 `npm test` 之後，「什麼都沒驗」和
「全部通過」對呼叫端是同一個訊號，CI 或 Ralph Loop 會誤判成通過。

**建議**：跳過時改用非 0 的離開碼（或至少獨立的碼，例如 77），讓呼叫端分得出來。

### I1 `info` — `s.seat` 寫了沒人讀

**位置**：[extension.js:436](../extension.js#L436)

`席に合わせる()` 結尾的 `if (s) s.seat = at;` 是唯一出現 `.seat` 的地方，全 repo 沒有任何
讀取端。死賦值，建議刪掉或改成真的有用途。

### I2 `info` — claim / handover 在多席位下已成死碼

改動後唯一非配對的橋是席 0（8765）。席 0 缺分頁時會寫 claim，但：

- 它自己的 `pollClaim` 看到 `c.port === openedPort` 就返回
- 其他席位都是配對模式，`pollClaim` 第一行就 return

所以**沒有任何一個橋會去執行那次讓渡**。這不是缺陷（「不互搶」正是本分支的目的），但
`claim.json` 的讀寫、`handover` 訊息、`br.tabElsewhere` 那組字串現在都是 vestigial。

保留是安全的（向後相容、且使用者顯式設定同埠時語意還在），但日後清理技術債時這一塊
可以整批拿掉。**本輪不動**——刪除會擴大變更面，而端對端驗收（T-008）都還沒跑。

### I3 `info` — 換席會改掉已開瀏覽器的 CDP 埠

**位置**：[extension.js:419-437](../extension.js#L419-L437)

`席に合わせる()` 會改 `browser` 的預設埠並 `確かめた口.clear()`。若換席發生時已經有開著的
瀏覽器頁面，那些 targetId 會指向舊埠而連不上。實務上換席只在啟動撞埠時發生（那時還沒有
任何瀏覽器頁面），所以列為 info。
