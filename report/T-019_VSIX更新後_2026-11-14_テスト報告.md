## 4. 確認された環境差異と注意点

- `code --version` と `code --list-extensions` は実行 PATH 上に `code` がなく `spawn code ENOENT` となった。これは **CLI パスの問題**であり、VSIX 自体の検証失敗ではない。`/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code` を指定して再実行し、両コマンドが成功した。
- **検証先の訂正：**実際に利用しているエディターは **VSCodium**。VSCodium の通常プロファイルを直接照会した結果、**`local.hadome@0.1.22` がインストール済み**で、更新 VSIX と ID・版が一致した。以前に VS Code（別アプリ）の一覧から見つかった `local.chatgpt-bridge@0.43.65` は VSCodium の導入版を示すものではなく、版違い・競合の根拠にはならない。その後、VSCodium の拡張機能ホストログで `local.hadome` のアクティベーションを確認し、橋接出力ログから Chrome Canary との握手および実際のツール結果の往復を確認した。既存の通常プロファイルは変更せず、追加のインストール検証は VSCodium 用の隔離ディレクトリで実施した。
- VSIX には `chrome-extension/` が同梱されるが、今回の Git 差分では同ディレクトリの変更は確認されていない。VSIX 検査だけでは Chrome 側の更新や通信を保証できないが、その後の実行ログで Chrome Canary との握手・基本通信は別途確認した。Chrome 拡張機能そのものの更新操作は行っていない。
- 専用の `lint` スクリプトは `package.json` に定義されていない。上記の `--check` は構文検証であり、linter の代替と称しない。
- 今回の操作でソースコード、既存の Git 変更、通常の VSCodium 拡張機能プロファイルは変更していない。隔離テスト用のインストールディレクトリ（VS Code 用、VSCodium 用）と本報告書を追加し、本報告書のエディター判定を修正した。

## 7. 追加検証：VSCodium／Chrome Canary 実通信および自動引き継ぎ

### 実環境で確認したこと

- VSCodium 拡張機能ホストログ（`20261114T190227/window1/exthost/exthost.log`）に、`local.hadome` が `onView:chatgptBridge.chatSecondary` でアクティベートされた記録がある。
- ローカルの TCP `127.0.0.1:8765` は VSCodium が LISTEN し、Chrome Canary の NetworkService と VSCodium の間で ESTABLISHED 接続を確認した。Chrome Canary 側のプロファイルには対象タブ用拡張機能が登録済み。
- VSCodium の「ChatGPT 橋接」出力ログに、対象タブからの `hello`、相方の版 `0.62.0`、実 ChatGPT 対話への送信、ツール呼び出し、ツール実行結果の返却、複数回合の処理、`state: done` が記録されている。これは基本的な往復通信の実証であり、自動引き継ぎの成功を意味しない。
- 追加確認時の Canary CDP `127.0.0.1:9444` は応答したが、そこで列挙されたページは 0 件だった。実 ChatGPT 対話の存在は当該 CDP 結果ではなく、上記の実運用ログで確認した。異なるプロファイル／実行中インスタンスの可能性を排除できないため、CDP だけで接続可否を判定しない。
