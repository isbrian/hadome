# T-019：自動上下文交接驗收報告

## 目的與範圍

在 hadome VS Code 擴充套件中加入可選擇啟用的上下文交接：當目前 ChatGPT 對話的**估算**上下文使用率達到 75%，且未有未完成的背景子代理時，於工具執行回合之間建立新對話，帶入原始目標、待辦狀態、最近工具結果與尚未送出的上一回合訊息，讓代理接著執行而非重新開始。

實際目標目錄：`/Volumes/ADATA_SE880/專案/GPT橋接器-大毛的/hadome`；驗證分支：`develop`。

## 實作內容

1. `src/auto-handoff.js`：集中管理 75% 門檻、估算用量、切換上限、背景作業判斷、交接摘要和具副作用工具呼叫指紋。不同參數／工具產生不同指紋；支援巢狀 `input` 與攤平參數。
2. `src/agent.js`：在新回合開始時檢查用量；呼叫 `bridge.newConversation`，確認 `fresh === true` 且可取得的對話 ID 不與舊對話相同；失敗則停止，避免在不明會話重試。成功時帶入原任務與執行紀錄、保留待辦及歷史、重置對話內部狀態；新對話首回合攔截交接前已成功執行的相同副作用操作。避免舊對話用量尚未重置時反覆觸發。
3. `src/bridge.js` 與 `src/conversation-lifecycle.js`：新增自動交接的生命週期原因與合法代理來源；一般手動／恢復路徑不可直接冒用自動交接原因。
4. `extension.js`、`package.json`、`package.nls*.json`：新增 `chatgptBridge.autoHandoff`（預設 `false`）及 `chatgptBridge.maxHandoffs`（預設 2、最多 10），使用原有的 `chatgptBridge.contextWindow` 設定；新增繁中、英文與日文的成功／失敗通知。
5. `test/auto-handoff.test.js`：門檻、未設定視窗、停用、背景作業、次數限制、指紋、交接資料及截斷測試。
6. `test/auto-handoff-integration.test.js`：以模擬 Bridge 真正跑代理回合，驗證成功交接續作、未確認新對話時安全停止、切換拋錯時不重送。

## 已驗證的安全邊界

- 預設**不會**自行建立新對話；需要啟用 `autoHandoff`，且明確設定上下文視窗上限。
- 上下文使用率由字數換算，**不是模型 API 的實測 token 用量**；上限未知時不猜測、不觸發。
- 有執行中的背景子代理時不切換；達設定交接次數上限時不再觸發。
- 新對話建立失敗、回傳不新鮮或無法確認時採停止策略，不再送出待執行內容。
- 交接摘要明確標註已成功操作不得重做，且保留原待辦與最後回合資料；過長的資料會標明截斷，要求必要時重新讀取。

## 限制及待人工驗證

本次**沒有**以使用者實際登入的 ChatGPT 分頁進行端到端操作，因此尚未驗證真實瀏覽器切換、專案歸屬、UI 延遲、重載後的會話 ID 及交接後續動作。整合測試使用模擬 Bridge，不能視為真人瀏覽器驗收。

手動驗收建議：在測試工作區設定可控的 `contextWindow`、開啟 `autoHandoff`，執行含多回合唯讀工具的任務，觀察約 75% 估算用量時是否只開一段新對話、待辦是否維持、上一輪結果是否傳入；再測試切換失敗時是否停止，以及已成功的寫入是否不會重做。正式使用請將視窗數值設成目標模型的實際可用範圍，勿以測試用小數值投入正式工作。
