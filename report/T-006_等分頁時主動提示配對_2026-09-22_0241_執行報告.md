## 需求說明

多席位功能上線後留下的可用性缺口：當 slot 0（8765）已被別的視窗占用，本視窗會自動換到 8766/8770/8771，但**未釘住的 chatgpt.com 分頁只會掃 8765**，所以第二個視窗會安靜地等一個永遠不會來的分頁。使用者必須自己知道要執行「開一個與本視窗配對的分頁」。

```js
const 誘い =
  portlock.slotIndexOf(s.bridge.port) > 0
    ? setTimeout(() => {
        post({
          type: 'note',

    : 0;
try {

} finally {

```

### 設計取捨

原本最直覺的做法是「開橋當下就把提示印出來」，但那會在**已經有釘住分頁、只是正在退避重連**的情境下誤導使用者——看到提示就再開一個分頁，結果同一個埠有兩個分頁，bridge 會記一筆「別のタブもつながっています」。

改為延遲 8 秒 + 只在 `slotIndexOf > 0` 時掛：

- slot 0 行為完全不變，一則多餘訊息都不會多
- 已釘住的分頁通常在 8 秒內就接上，接上後 `finally` 會把計時器清掉，提示不會出現
- 真的沒分頁時，8 秒後看到提示，遠早於 `waitForTab()` 30 秒逾時才報錯
- 文案用「還沒連上」起頭而非命令句，即使在分頁稍後才接上的邊緣情況也不會講錯話

計時器在面板已關閉時才觸發也是安全的——`send()` 有 `if (view)` 防護（[extension.js:211-213](../extension.js#L211-L213)）。
